## 1. 这个项目练什么

前两个项目（房价、手写数字）的数据都是"洗干净喂到嘴边"的：特征全是数值、没有缺失、没有类别变量。真实世界的表格数据完全不是这样。泰坦尼克数据集是表格类机器学习的"Hello World"，它的教学价值不在比赛分数，在于**几乎每种表格数据的坑都占全了**：

| 坑 | 泰坦尼克里的活例 | 对应技能 |
|---|---|---|
| 缺失值 | `age` 约两成缺失、`embarked` 缺失 2 条、`cabin` 大面积缺失 | 有状态填补（§3） |
| 类别特征 | `sex`、`embarked`、`pclass` | 编码（§3） |
| 高基数文本 | `name`、`ticket`、`cabin` | 取舍与特征工程（§4） |
| **数据泄漏** | `boat`（救生艇编号）、`body`（遗体编号） | 泄漏识别（§5，本项目最有价值的一课） |
| 类别不平衡 | 约 38% 获救 | 指标选择 + `scale_pos_weight`（前置文档 §11.7） |
| 小数据 | 仅 1309 行 | 交叉验证的必要性（前置文档 §11.4） |

## 2. 数据集

通过 OpenML 获取（sklearn 内置接口，免注册），共 1309 名乘客，目标列 `survived`（1=获救，0=遇难）。

| 字段 | 类型 | 含义 | 本项目用法 |
|---|---|---|---|
| `pclass` | 类别 | 舱位等级（1/2/3 等舱） | ✅ 数值特征（等级天然有序） |
| `sex` | 类别 | 性别 | ✅ 二值编码 |
| `age` | 数值 | 年龄（约两成缺失） | ✅ 中位数填补 |
| `sibsp` | 数值 | 同行的兄弟姐妹/配偶数 | ✅ 直接用 + 组合特征 |
| `parch` | 数值 | 同行的父母/子女数 | ✅ 直接用 + 组合特征 |
| `fare` | 数值 | 票价（1 条缺失） | ✅ 中位数填补 |
| `embarked` | 类别 | 登船港口（C/Q/S，2 条缺失） | ✅ 众数填补 + one-hot |
| `name` | 文本 | 姓名 | ❌ 入门版弃用（进阶：可提取 Title） |
| `ticket` | 文本 | 票号 | ❌ 弃用（高基数） |
| `cabin` | 文本 | 客舱号（大面积缺失） | ❌ 入门版弃用 |
| `home.dest` | 文本 | 目的地 | ❌ 弃用 |
| `boat` | 文本 | 救生艇编号 | 🚫 **泄漏列，必须删** |
| `body` | 数值 | 遗体识别编号 | 🚫 **泄漏列，必须删** |

`data/download.py` 已实现：优先读本地缓存 `data/raw/titanic.csv`，没有则 `fetch_openml` 拉取并缓存。

## 3. 核心工程课：有状态预处理与"先划分、再 fit"

模块 2 的像素归一化是**无状态**的（除以常数 16/255，不需要从数据统计任何量），所以先处理还是先划分无所谓。本项目不一样：

- `age` 的缺失值要填**中位数**——中位数是从数据里统计出来的！
- `embarked` 要填**众数**——也是统计出来的；
- one-hot 的**列清单**——取决于训练集里出现过哪些类别。

这类预处理叫**有状态变换**。它的铁律（前置文档 §11.4 铁律 2 的项目版）：

```
1. 先划分 train / test
2. 状态（中位数、众数、列清单）只在 train 上 fit
3. 用这份状态分别 transform train 和 test
4. 状态随模型一起打包保存，predict.py 复现同一套变换
```

如果先全量填补再划分：测试集的"平均年龄"悄悄混进了训练集的中位数里——**数据泄漏**，测试分数虚高 0.001~0.01 且不可复现到生产。泄漏量小，但**范式是错的**；生产环境里测试集根本不存在，你连"虚高"的机会都没有。

`features.py` 因此设计成三个函数（签名即流程）：

```python
train_df, test_df = split_data(df, config)          # ① 先划分
X_train, y_train, state = fit_preprocessor(train_df, config)   # ② 只在 train 上 fit
X_test, y_test = transform(test_df, state, config)             # ③ 同一状态 transform
```

`state` 是一个 dict（各列填补值、特征列清单、特征开关快照），`train.py` 会把它和模型一起打包进 `models/model.joblib`——预测时永远能复现训练时的预处理。

## 4. 特征工程

入门版做四件事（都有测试护航）：

1. **删泄漏列**：`boat`、`body`（§5 详解为什么是泄漏）；
2. **删高基数文本列**：`name`、`ticket`、`cabin`、`home.dest`；
3. **填补**：`age`/`fare` 填训练集**中位数**（中位数比均值抗离群值——票价有 500 多的天价票），`embarked` 填训练集**众数**；
4. **编码 + 组合**：
   - `sex` → `sex_male`（男=1，女=0）；
   - `embarked` → one-hot 三列 `embarked_C / embarked_Q / embarked_S`；
   - 组合特征 `family_size = sibsp + parch + 1`（家庭总人数）、`is_alone = (family_size == 1)`——"是否独自登船"在泰坦尼克里是强信号（独自一人的成年男性存活率显著低于有家庭的）。

注意一件事：**全程没有特征缩放**。这是刻意的——树模型只看排序不看尺度（前置文档 §1.4），标准化在树项目里是多余动作。你可以把它加回去跑一遍对比，会发现分数纹丝不动，这个实验本身就值得做。

进阶自选（完成主线后再玩）：从 `name` 提取 `Title`（Mr/Mrs/Miss/Master…）——"Mrs"和"Miss"的存活率差异巨大，这是 Kaggle 上泰坦尼克帖子里最经典的特征工程；把 `cabin` 的首字母提取成甲板层。每加一个特征，重跑 CV 对比分数。

## 5. 泄漏列：本项目最贵的一课

`boat`（获救时登上的救生艇编号）和 `body`（遇难后的遗体编号）——想一想：**有救生艇编号 ⟺ 上了救生艇 ⟺ 大概率获救；有遗体编号 ⟺ 确认遇难**。这两列几乎是答案本身的另一种写法。

留着它们训练，任何模型测试准确率都会冲到 95%+，漂亮得像作弊——因为就是作弊。这教你一个比任何调参技巧都值钱的意识：**看到一个特征好得不正常时，第一反应应该是怀疑泄漏，而不是庆祝**。生产环境里泄漏特征不存在（事故发生时救生艇编号还没分配），模型上线即报废。

判断口诀：**这个特征在"需要做预测的那个时刻"就已经可得了吗？** 登船时可知 → 可用；事故结局已定才产生 → 泄漏。

## 6. 模型对比：三代同堂

`model.py` 的工厂支持四个名字（`config.yaml` 里 `model.name` 切换）：

| name | 模型 | 定位 | 关键参数 |
|---|---|---|---|
| `decision_tree` | sklearn DecisionTreeClassifier | 手写练习的调库版，基线 | `max_depth` 必给（前置文档 §5） |
| `random_forest` | sklearn RandomForestClassifier | bagging 路线 | `n_estimators` + `oob_score`（§9） |
| `lightgbm` | LGBMClassifier | boosting 路线主力 | 全套（§11） |
| `xgboost` | XGBClassifier | 对比用（§12） | 与 lightgbm 平行 |

建议的实验顺序（也是任务清单，§7 的打分依据）：

1. **决策树基线**：`max_depth=None` 跑一次，再 `max_depth=5` 跑一次——亲眼看不剪枝的过拟合（train/test 分差）；
2. **随机森林**：默认 300 棵树 + `oob_score=True`，对比 OOB 分数和测试分数的接近程度；
3. **LightGBM 默认参数**：通常已经比前两个好——boosting 的威力；
4. **LightGBM 调参**（`tune.py`，§7 的核心）：四轮法走一遍；
5. **XGBoost 对比**：同量级参数跑一遍，写两句差异观察。

## 7. tune.py 与调参报告

`tune.py` 是本项目的心脏脚本，把前置文档 §11.5 的四轮法落成代码：

```
stage 0  baseline：默认参数 + 5 折分层 CV
stage 1  骨架：固定 lr=0.05、n_estimators=2000 上限，逐折早停，取最优轮数中位数
stage 2  结构：num_leaves × min_child_samples 网格 + CV
stage 3  采样：feature_fraction × bagging_fraction 网格 + CV
stage 4  正则 + 收尾：lambda_l2 网格；lr 降到 0.02 再早停一次
每个 stage 记录 CV 分数（mean ± std），最后生成 reports/tuning_report.md
```

报告模板（脚本自动生成，你填"观察与结论"列）：

| Stage | 试了什么 | CV 分数（mean ± std） | 观察与结论 |
|---|---|---|---|
| 0 | 默认参数 | … | … |
| 1 | lr=0.05 + 早停 | … | 最优轮数多少？过拟合了吗 |
| 2 | num_leaves ∈ {15,31,63} | … | 小数据上叶子多了有用吗 |
| 3 | 采样比例 | … | 去相关对这份数据有效吗 |
| 4 | L2 正则 + lr 收尾 | … | 最终配置 vs 默认参数的提升 |

**评分标准不是最终准确率**——1309 行数据上大家都落在 0.80~0.84。评分标准是：报告里每个 stage 有没有一句"我观察到什么、下一步因此怎么调"。调参报告的肌肉记忆 = 工业界建模的日常。

## 8. 任务清单

1. **跑通基线**：`pytest tests/ -v` 看失败清单 → 实现 `features.py` 三个函数 → 测试变绿 → `python train.py`；
2. **泄漏实验**（5 分钟，必做）：把 `features.py` 里的 `LEAKAGE_COLS` 注释掉重新训练，看测试准确率冲到多少，再改回来——亲眼看一次"作弊的分数"；
3. **三代对比**：按 §6 的顺序跑四个模型，记录各自的测试集 accuracy / F1 / ROC-AUC；
4. **调参报告**：跑通 `tune.py` 全部 stage，填好"观察与结论"，产出 `reports/tuning_report.md`；
5. **特征重要性**：`evaluate.py` 会画三种重要性对比图（split/gain/permutation），回答：这份数据里最重要的三个特征是什么？三种口径的排序一致吗？
6. **推理 demo**：`python predict.py --pclass 3 --sex male --age 22 --sibsp 1 --parch 0 --fare 7.25 --embarked S` 预测一个虚拟乘客；
7. （进阶）Title 提取特征，重跑对比 CV 分数。

## 9. 常见坑

- **`fetch_openml` 需要联网**，首次运行下载后缓存在 `data/raw/titanic.csv`，之后离线可用；
- OpenML 的 `pclass` 是文本型（`"1st"/"2nd"/"3rd"` 或 `"1"/"2"/"3"`，版本间有差异），`download.py` 里已统一提取数字转成 1/2/3——别在 features.py 里再处理一遍；
- **填补值必须来自训练集**（§3），测试里有一条专门验证这个性质，写错了会变红；
- LightGBM 4.x 的早停用 `callbacks=[lgb.early_stopping(50)]`，网上老教程里的 `fit(early_stopping_rounds=50)` 已移除；
- LightGBM 对 pandas 的 object 列会报 warning 或静默转错——`transform` 出口处确保所有列都是数值型（测试里有 `assert X.dtypes` 一关）；
- 树模型吃 one-hot 没问题，不需要 drop_first（那是线性模型防共线性的讲究）；
- 测试集只在最后评估用一次；调参全程 CV（§11.4 铁律 1）。
