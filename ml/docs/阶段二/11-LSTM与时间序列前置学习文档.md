**贯穿全文的例子**：机房温度监控。你有一台服务器机房的历史温度（每小时一个点，2000 个小时点），想预测"明天的下一个小时是多少度"。合成这份数据（后面所有章节都用它）：

```python
import numpy as np

rng = np.random.default_rng(42)
t = np.arange(2000)
temp = 20 + 8 * np.sin(2 * np.pi * t / 24) + 4 * np.sin(2 * np.pi * t / 168) \
       + 0.002 * t + rng.normal(0, 0.5, len(t))

print(temp.mean().round(2), temp.std().round(2))   # 22.0 6.4
```

规律一句话：**日周期**（24 小时一循环，幅度 8 度）+ **周周期**（168 小时，幅度 4 度）+ 缓慢上升 + 噪声。注意数据是有顺序的——把第 500 行和第 501 行对调，物理意义就变了。**顺序本身就是信息**，这是时序数据和模块 4 图像数据的本质区别。

## 1. 时序问题与"记忆"：为什么 MLP 不够 🟢

### 1.1 是什么（直觉）

预测"下一个小时温度"最朴素的思路：**把过去 24 个小时排平成一个 24 维向量，喂给 MLP**（模块 4 的老朋友）。这能跑，但有三个结构性缺陷：

1. **参数浪费**：第 1 小时和第 24 小时的权重是两个独立参数，模型要分别为"24 小时前的温度"和"1 小时前的温度"学一套系数——但它们在物理上是同一个"温度对下一小时的贡献"，只是时间位置不同；
2. **不能变长**：换成"用过去 48 小时预测"，输入维度变了，整个模型要重训；
3. **没有记忆的复用**：人看温度曲线不是把 24 个数字排开一次看完，而是**逐个时间点读入、边读边更新对"当前状态"的印象**。

带"记忆"的模型 = **循环神经网络（RNN）**：一个隐状态 h 从序列开头一路传到结尾，每个时间步用同一个函数更新它。**同一组参数在所有时间步之间共享**——三个缺陷一次解决。

### 1.2 实测：MLP 展平 vs LSTM，同一份数据正面对比

用过去 24 步预测下一步（滑动窗口的构造 §6 细讲，这里先看结论），两套模型都真实训练 30 个 epoch：

| 模型 | 输入 | 参数量级 | 测试 RMSE（反归一化，度） |
|---|---|---|---|
| MLP（24→64→1） | 24 维展平 | ~2K | **1.1167** |
| LSTM（hidden=32，2 层） | 24 个时间步逐个读入 | ~13K | **0.8043** |

LSTM 把误差从 1.12 度压到 0.80 度。**为什么**：温度预测的关键是"现在处于日周期的哪个相位"——LSTM 用隐状态一路记录着"过去 24 小时的走势形状"，天然比一排独立权重更擅长抓这种模式。这不是 LSTM 万能，而是**归纳偏置（时间共享参数）和数据结构（时间规律）对上了**。

**本节小结**：时序数据顺序即信息。展平喂 MLP 能跑但浪费参数、不能变长；RNN 用一个隐状态 + 全时间步共享参数解决了这三件事。

## 2. RNN：结构与致命伤 🟢

### 2.1 RNN 的结构（一句话版）

```
h_t = tanh(W·[x_t, h_{t-1}] + b)      —— 每个时间步执行一次
```

**逐符号翻译**：`x_t` 是第 t 个时间步的输入（比如当前小时的温度）；`h_{t-1}` 是上一步传下来的**隐状态**（"到目前为止的记忆"）；把两者拼接 `[x_t, h_{t-1}]` 乘同一个 W、加偏置、过 tanh，得到新的记忆 `h_t`。序列读完后，最后一个 `h_T` 就是"整个序列的摘要"，接个 Linear 就能做预测。

关键认识：**每一步用的都是同一个 W**（参数共享），所以"预测下一个温度"的规律只学一次，所有时间步复用。

### 2.2 致命伤：梯度消失（时序版）

训练要用反向传播把梯度从最后一个时间步传回第一个（模块 4 文档 §6 讲过 MLP 版的梯度消失）。RNN 的梯度要**沿时间**一步步传回去，每传一步都要乘一次 `tanh'`——而 `tanh' ≤ 1`，且实际取值往往远小于 1（tanh 大部分时间工作在饱和区）。

连乘 100 步会发生什么？实测（`z` 取 0~3 之间的典型值，逐步累乘 `tanh'`）：

```python
import numpy as np

z = np.linspace(0, 3, 100)                       # tanh 大多工作在饱和区附近
prods = np.cumprod(1 - np.tanh(z) ** 2)          # 逐步累乘 tanh'
print(prods[-1])                                 # 7.269492771787441e-83
```

**10⁻⁸³**。第 1 个时间步收到的梯度约等于"宇宙里一个原子的重量比上一头鲸鱼"。sigmoid 更惨：`sigmoid' ≤ 0.25`，连乘 100 步上限是 `0.25¹⁰⁰ ≈ 6.22e-61`（这还是理论最大值）。

这就是 RNN 的致命伤：**名义上有记忆，实际只有"金鱼记忆"**——梯度传不了几十步，序列开头的 信息根本学不到。LSTM 就是为修这个洞而生的。

**本节小结**：RNN = 隐状态 + 参数共享，但梯度沿时间连乘 `tanh'`（≤1）指数衰减，100 步后只剩 1e-83——记不长。

## 3. LSTM 直觉：细胞状态传送带 + 三道门 🟢

### 3.1 核心设计：给记忆修一条"高速公路"

RNN 的记忆每一步都被**整个重写**（`h_t = tanh(W·[...])`），旧记忆想活到 100 步之后，就要在 100 次"重写"中幸存——难如登天。

LSTM 的解法漂亮的出人意料：**把"长期记忆"单独放到一条传送带（细胞状态 c）上，默认情况下原样往前送，只在明确需要时才修改**：

```
c_t = f ⊙ c_{t-1}  +  i ⊙ g̃      —— 加法更新！不是重写
```

**逐符号翻译**：

- `c`（cell state）：**长期记忆传送带**，走主干道；
- `f`（forget gate，遗忘门）：一个 0~1 的开关向量，控制**旧记忆保留多少**（f≈1 原样保留，f≈0 清零）；
- `i`（input gate，输入门）：控制**新内容写入多少**；
- `g̃`（candidate，候选记忆）：本次想写入的新内容（tanh 产生的 -1~1 值）；
- `⊙`：**逐元素相乘**（Hadamard 积），形状相同的两个向量对应位置相乘。

**为什么加法更新能治梯度消失**：模块 4 文档 §6 讲过，梯度消失的根源是"每一步都乘一个 <1 的数"。而 `c_t = f ⊙ c_{t-1} + i ⊙ g̃` 里，梯度沿 c 这条路回传时走的是**加法的分支**——当 f≈1（模型学会"这段记忆别忘"），梯度就像走高速公路一样几乎无损地流过几十上百个时间步。**门是可学习的**：模型自己决定每条记忆通道"忘多少、记多少"。

### 3.2 三道门的分工（类比版）

把 LSTM 想成一个档案室管理员：

| 门 | 类比 | 数学角色 | 激活函数 |
|---|---|---|---|
| 遗忘门 f | 决定旧档案**保留几成** | 过滤上一步的细胞状态 c_{t-1} | sigmoid（输出 0~1 开度） |
| 输入门 i | 决定新档案**收录几成** | 过滤新内容 g̃ | sigmoid |
| 输出门 o | 决定档案**对外展示几成** | 过滤 tanh(c_t)，得到对外的 h_t | sigmoid |

以及一个不属于门的角色：

| 候选记忆 g̃ | 要写进档案的**新内容草稿** | 和 i 相乘后加进 c | tanh（输出 -1~1 数值） |

记住一句口诀：**sigmoid 管门（开度），tanh 管内容（数值）**。

**本节小结**：LSTM = 细胞状态 c 走加法更新的传送带 + 三道可学习的 sigmoid 门（遗忘/输入/输出）+ tanh 候选内容。梯度沿加法分支无损流动，长程记忆得以存活。

## 4. LSTM 公式逐个拆解 🟢（核心，手写练习直接考）

六个公式，一个都不能跳：

```
① i_t = σ(W_i·[h_{t-1}, x_t] + b_i)     输入门（0~1）
② f_t = σ(W_f·[h_{t-1}, x_t] + b_f)     遗忘门（0~1）
③ g̃_t = tanh(W_g·[h_{t-1}, x_t] + b_g)  候选记忆（-1~1）
④ o_t = σ(W_o·[h_{t-1}, x_t] + b_o)     输出门（0~1）
⑤ c_t = f_t ⊙ c_{t-1} + i_t ⊙ g̃_t      细胞状态更新（传送带！）
⑥ h_t = o_t ⊙ tanh(c_t)                 隐状态 = 门控后的细胞状态
```

**形状账**（手写和调库都绕不开，必须一次算清）：设输入维度 `input_size`、隐状态维度 `hidden_size`、batch 大小 B：

| 张量 | 形状 | 说明 |
|---|---|---|
| x_t | (B, input_size) | 当前时间步输入 |
| h_{t-1}, c_{t-1} | (B, hidden_size) | 上一步的记忆 |
| [h_{t-1}, x_t] 拼接 | (B, input_size + hidden_size) | 拼接是**列方向**拼 |
| 每个 W | (4·hidden, input_size + hidden) | 四个门可以合成一个大矩阵（torch 就是这么存的） |
| i_t, f_t, g̃_t, o_t | (B, hidden_size) 各一个 | 每个门都是 hidden 维的开关向量 |
| c_t, h_t | (B, hidden_size) | 传给下一步 |

### 4.1 手算一遍单步前向（全部真实数字）

用 numpy 把六个公式走一遍（input_size=2, hidden=2, batch=1，参数由 `default_rng(0)` 生成）：

```python
import numpy as np

rng = np.random.default_rng(0)
params = {
    "W_ih": rng.uniform(-0.5, 0.5, (8, 2)),   # 4 门 × hidden=2 → 8 行
    "W_hh": rng.uniform(-0.5, 0.5, (8, 2)),
    "b_ih": rng.uniform(-0.5, 0.5, 8),
    "b_hh": rng.uniform(-0.5, 0.5, 8),
}
x_t, h_prev, c_prev = np.array([[1.0, 0.5]]), np.array([[0.2, -0.1]]), np.array([[1.0, -0.5]])

z = x_t @ params["W_ih"].T + params["b_ih"] + h_prev @ params["W_hh"].T + params["b_hh"]
i, f, g, o = z[:, :2], z[:, 2:4], z[:, 4:6], z[:, 6:8]        # ⚠️ 顺序 i,f,g,o
sig = lambda x: 1 / (1 + np.exp(-x))
i, f, o, g = sig(i), sig(f), sig(o), np.tanh(g)
c_t = f * c_prev + i * g
h_t = o * np.tanh(c_t)
print("i =", i.round(4), "f =", f.round(4), "g =", g.round(4), "o =", o.round(4))
# i = [[0.4494 0.3341]]  f = [[0.6417 0.4723]]  g = [[0.1716 0.7155]]  o = [[0.5763 0.5243]]
print("c_t =", c_t.round(4))     # [[0.7188 0.0029]]（c_prev = [[ 1. -0.5]]）
print("h_t =", h_t.round(4))     # [[0.3551 0.0015]]
print(round(float(c_t[0, 0]), 4), "==", round(float(f[0,0]*1.0 + i[0,0]*g[0,0]), 4))
# 0.7188 == 0.7188 —— 公式 ⑤ 逐数字对上
```

把第 0 号记忆通道的账手工过一遍：`c_t = f·c_prev + i·g̃ = 0.6417×1.0 + 0.4494×0.1716 = 0.7188`。旧记忆留下 64%，新内容写入 7.7%——**"忘"和"记"在同一行公式里同时发生**，这就是 LSTM 的全部魔法。

**⚠️ 全练习最大的坑**：四个门的拼接顺序是 **i, f, g, o**（PyTorch 官方约定）。很多教材按 f, i, o, g 的顺序写公式——顺序记错，对答案时一切全错。

### 4.2 门的开关行为（教学性验证）

门的物理意义可以直接用偏置钳出来（权重置零、只留偏置说话）：

- f 门偏置设 **+10**：`f = σ(10) ≈ 0.99995 ≈ 1` → 旧记忆几乎无损保留（i 门同时关死 → c_t ≈ c_prev，一字不差）；
- f 门偏置设 **−10**：f ≈ 0 → 旧记忆被彻底清零；
- i 门关死、g 拉满：新内容再好也写不进传送带。

手写练习的测试里就埋了这三条行为断言——**门不是数学装饰，是可学习的记忆开关**。

**本节小结**：六个公式两条线——①~④ 四个门（sigmoid/tanh）算"开度"和"内容"，⑤⑥ 更新记忆（c 加法传送、h 门控输出）。形状账 + 门顺序 i,f,g,o + "sigmoid 管门 tanh 管内容"，三件事刻死。

## 5. PyTorch nn.LSTM 实战 🟢（P1 主战场）

### 5.1 形状全家桶（一次实测，终生受用）

```python
import torch
from torch import nn

torch.manual_seed(42)
lstm = nn.LSTM(input_size=1, hidden_size=32, num_layers=2, batch_first=True)
X = torch.randn(5, 24, 1)                      # (batch=5, seq_len=24, input_size=1)
out, (h_n, c_n) = lstm(X)
print(out.shape, h_n.shape, c_n.shape)
# torch.Size([5, 24, 32]) torch.Size([2, 5, 32]) torch.Size([2, 5, 32])
print(torch.allclose(out[:, -1, :], h_n[-1]))  # True —— 两种写法等价！
```

**逐个翻译**：

| 返回值 | 形状 | 含义 |
|---|---|---|
| `out` | (batch, seq_len, hidden) | **每个时间步**的顶层隐状态——整个序列的逐步记录 |
| `h_n` | (num_layers, batch, hidden) | **最后一个时间步**的隐状态，**按层**堆叠 |
| `c_n` | (num_layers, batch, hidden) | 最后一个时间步的细胞状态，按层堆叠 |

三个必踩的坑，一次踩完：

1. **`batch_first=True` 必须显式写**。torch 默认布局是 (seq, batch, feature)——论文时代的遗留习惯。忘写这个参数，你的数据会被当成"240 步的 batch=5"之类的鬼东西，不报错，只是默默给出错误结果；
2. **取"最后一个时间步"做预测有两种等价写法**：`out[:, -1, :]` 或 `h_n[-1]`（实测 `allclose` 为 True）——前者直观（时间步维取最后），后者快（不用留整个 out）；
3. **h_n/c_n 的 batch 维夹在中间**（num_layers 在最前）——与 batch_first 与否无关，这是层维，不是数据维。

### 5.2 完整训练：LSTM 预测机房温度

```python
class LSTMForecaster(nn.Module):
    def __init__(self):
        super().__init__()
        self.lstm = nn.LSTM(1, 32, 2, batch_first=True)
        self.head = nn.Linear(32, 1)          # 回归任务：末层无激活（输出任意实数）
    def forward(self, x):                     # x: (batch, 24, 1)
        out, _ = self.lstm(x)                 # (batch, 24, 32)
        return self.head(out[:, -1, :])       # 取最后时间步 → (batch, 1)

# 训练循环与模块 4 的五步法完全一致（forward → loss → zero_grad → backward → step）
# 数据：§6 的滑动窗口，X (1392, 24, 1) → y (1392, 1)，Adam(lr=1e-3)，30 epoch
# 实测结果（seed=42）：
#   MLP  测试 RMSE = 1.1167 度
#   LSTM 测试 RMSE = 0.8043 度   ← §1 表格的出处
#   naive（预测 = 上一个小时）RMSE = 1.6603 度
```

三行实测结论值得嚼一遍：LSTM(0.80) < MLP(1.12) < naive(1.66)。温度有强日周期，naive"下小时=这小时"在温度爬坡时段错得离谱；LSTM 从隐状态里读出了周期相位，所以大幅领先。**注意顺序不是永远这样**——模块 6 项目的 ETTh1 实测里 naive 非常顽固（§7 详谈）。

### 5.3 多层 LSTM 与 dropout 一句话

`num_layers=2` 表示两层 LSTM 堆叠：第一层的输出序列 `out` 作为第二层的输入序列（这也是为什么 `h_n` 按 (num_layers, batch, hidden) 排）。`dropout` 参数只在层与层之间生效，`num_layers=1` 时必须为 0（torch 会报错提醒你）。本模块只用到单层/双层，更多层属于调参范畴。

**本节小结**：`nn.LSTM` 三件返回值（out / h_n / c_n）的形状全家桶 + `batch_first=True` 铁律 + `out[:,-1,:] ≡ h_n[-1]`。训练循环与模块 4 五步法一字不差。

## 6. 滑动窗口与时序泄漏 🟢（工程化核心）

### 6.1 滑动窗口：把长序列切成监督学习样本

监督学习要 (X, y) 对。时序数据的切法：**用过去 window 步预测未来 horizon 步**，窗口沿时间轴每次滑动 1 步：

```
窗口 1: [t0  t1  ... t23] → t24      （horizon=1 时）
窗口 2: [t1  t2  ... t24] → t25
窗口 3: [t2  t3  ... t25] → t26
```

```python
import numpy as np

def make_windows(series, window, horizon=1):
    X = np.lib.stride_tricks.sliding_window_view(series, window + horizon)[:-1]
    return (X[:, :window].reshape(-1, window, 1).astype(np.float32),   # (n, window, 1)
            X[:, window:].astype(np.float32))                          # (n, horizon)

X, y = make_windows((temp - 20) / 10, 24, 1)
print(X.shape, y.shape)     # (1975, 24, 1) (1975, 1) —— 2000 个点切出 1975 个窗口
```

对齐关系（写测试时逐索引断言它）：第 i 个窗口的最后一行是 `series[i + window - 1]`，目标的第一行是 `series[i + window]`——**预测绝不偷看窗口内部的信息**。

### 6.2 时序数据不能随机划分（本文最重要的工程纪律）

模块 4 的图像数据怎么切都行，因为样本独立。时序数据第 t 行和第 t+1 行几乎一样——**随机划分 = 训练集里塞满测试点的邻居**，模型靠"背邻居"就能蒙对，评估数字虚假偏高。

实测（随机游走 + 漂移序列，线性回归，同样的"未来"测试窗口）：

| 训练方式 | 1 步预测 RMSE | 10 步预测 RMSE |
|---|---|---|
| 按时间切（训练段止于 80% 处） | **0.987** | **2.607** |
| 随机划分（训练集混入未来窗口） | 0.926 | 2.317 |

预测步数越长泄漏的收益越大——**评估虚高在"最难的地方"最严重**，而那正是你部署后真正面对的场景。纪律三条：

1. **按时间先后切** train/val/test（如 70/15/15），val 和 test 都在时间轴的"未来"；
2. **窗口在各段内部独立构造**：跨越 train/val 边界的窗口，输入带着训练段末尾、目标却在验证段——同一种泄漏的变种；
3. **标准化统计量只用训练段算**（和模块 1 的 StandardScaler 同一个坑）。

附带一个反直觉点：**窗口化之后的 train_loader 反而要 `shuffle=True`**——打乱的是"窗口样本的顺序"（SGD 的正常要求），不破坏任何窗口内部的时间结构。与"打乱原始时间点"是两回事。

**本节小结**：滑动窗口 = 时间轴上的 (X, y) 生产线；时序三纪律——按时间切、段内开窗、训练段定统计量。

## 7. 多步预测与评估 🟡

### 7.1 naive baseline：时序预测的"及格线"

**naive forecast**：预测 = 窗口最后一个值（"下小时 = 这小时"）。它不是段子——它是衡量"你的模型有没有赚到超过惯性的钱"的硬标尺。**时序项目的铁律：任何模型报告必须并排 naive，打不过 naive 就是白干**（前置文档 §7 的原话）。

两个真实场景的实测对照：

| 数据集 | 模型 | naive | 结论 |
|---|---|---|---|
| 本文合成温度（日周期强） | LSTM RMSE 0.804 | 1.660 | LSTM 大胜（周期相位可学） |
| ETTh1 油温（模块 6 项目，horizon=4） | LSTM RMSE 1.044 | 1.075 | RMSE 小胜，MAE 打平略输 |

同一个 naive，一个被完爆、一个打不动——**naive 的强弱取决于数据的自相关结构**。强周期数据上 naive 笨（看不出周期），强惯性数据上 naive 狡猾（复制粘贴就是最优解之一）。动手前先算一眼 naive，你才知道自己要打赢的是谁。

### 7.2 多步预测的两种做法

- **直接多输出**（本文项目采用）：末层 Linear 输出 horizon 个值，一次算完。训练目标明确，误差不累积；
- **递归滚动**：模型只预测 1 步，把预测值塞回输入再预测下一步，滚 horizon 次。训练数据多（任何窗口长度都能当输入），但**误差逐步累积**——第 10 步吃的是 9 步的预测误差。

评估指标回到回归三件套 MAE/RMSE（模块 1 文档 §7.1），且**必须反归一化回原始单位再汇报**（"油温差 0.74 度"有人懂，"MSE=0.0134"没人懂）。

**本节小结**：先算 naive 再动手；直接多输出 vs 递归滚动各有代价；汇报指标必须带单位。

## 完整速查表

**概念**：时序数据顺序即信息 ｜ RNN = 隐状态 + 参数共享 ｜ 梯度沿时间连乘 tanh'（≤1）→ 记不长 ｜ LSTM = 细胞状态 c 加法传送带 + 三道门 ｜ 门 = sigmoid 开度向量，⊙ = 按开度放行 ｜ 时序划分按时间切、段内开窗、训练段定统计量 ｜ naive baseline 是及格线

**公式**：

| 名称 | 公式 | 一句话 |
|---|---|---|
| RNN | h_t = tanh(W·[x_t, h_{t-1}] + b) | 每步重写记忆 |
| 输入门 | i_t = σ(W_i·[h, x] + b_i) | 新内容写入开度 |
| 遗忘门 | f_t = σ(W_f·[h, x] + b_f) | 旧记忆保留开度 |
| 候选记忆 | g̃_t = tanh(W_g·[h, x] + b_g) | 待写入的新内容 |
| 输出门 | o_t = σ(W_o·[h, x] + b_o) | 对外展示开度 |
| 细胞更新 | **c_t = f_t ⊙ c_{t-1} + i_t ⊙ g̃_t** | 加法传送带（防梯度消失的关键） |
| 隐状态 | h_t = o_t ⊙ tanh(c_t) | 门控后的输出 |
| naive | ŷ_{t+1} = y_t | 下一步 = 当前 |

**代码**（PyTorch）：

| 需求 | 写法 |
|---|---|
| 建模型 | `nn.LSTM(input_size, hidden_size, num_layers, batch_first=True)` |
| 前向 | `out, (h_n, c_n) = lstm(x)` |
| out / h_n / c_n 形状 | `(B, L, H)` / `(layers, B, H)` / `(layers, B, H)` |
| 取最后时间步 | `out[:, -1, :]`（等价 `h_n[-1]`） |
| 回归预测头 | `nn.Linear(hidden, horizon)`，末层无激活 |
| 滑动窗口 | `np.lib.stride_tricks.sliding_window_view(series, window + horizon)` |
| 回归损失 | `nn.MSELoss()`（模块 1/6 项目一致） |

## 自测题（附答案）

1. **（MLP 的缺陷）** 把过去 24 小时展平喂 MLP 做时序预测，三个结构性缺陷是什么？
2. **（梯度消失）** RNN 的梯度为什么会沿时间消失？tanh' 的理论上限是多少？sigmoid' 呢？
3. **（传送带）** `c_t = f ⊙ c_{t-1} + i ⊙ g̃` 里哪一项是"防梯度消失"的关键设计？为什么？
4. **（门的行为）** 想让 LSTM"把 50 步前的信息一字不差带到今天"，f 和 i 的偏置应该怎么设？
5. **（形状账）** `nn.LSTM(1, 32, 2, batch_first=True)` 喂 (5, 24, 1) 的输入，out / h_n / c_n 各是什么形状？
6. **（batch_first）** 忘写 `batch_first=True` 会发生什么？报错吗？
7. **（时序泄漏）** 三条时序划分纪律是什么？"窗口化之后 train_loader 反而要 shuffle=True"矛盾吗？
8. **（naive）** 两个数据集上 naive 一个被打爆一个打不动，为什么？动手建模前应该先做什么？

### 参考答案

**1.** ①每个时间位置的权重独立，参数浪费（同一物理规律要学 24 遍）；②输入维度固定，换窗口长度就得重训；③没有跨时间步的参数共享与记忆复用。

**2.** 梯度回传每跨一个时间步就乘一次激活函数的导数，tanh' ≤ 1 且常远小于 1，连乘指数衰减——实测典型值连乘 100 步只剩 7.3e-83。tanh' 上限 1（z=0 处）；sigmoid' 上限 0.25（0.25¹⁰⁰ ≈ 6.2e-61）。

**3.** 加法项 `f ⊙ c_{t-1}`。梯度沿 c 回传时走加法分支，f≈1 时几乎无损地流过任意长时间步；RNN 的重写式更新则每步都乘 tanh'，指数衰减。

**4.** f 门偏置设大正数（f≈1：旧记忆全保留），i 门偏置设大负数（i≈0：新内容不干扰）。手写练习里 f=+10、i=−10 时实测 c_t ≈ c_prev。

**5.** out (5, 24, 32)；h_n (2, 5, 32)；c_n (2, 5, 32)。

**6.** 不报错。torch 默认按 (seq, batch, feature) 解释你的 (5, 24, 1)，等于把 5 当序列长、24 当 batch——训练照跑，结果默默变垃圾。

**7.** 按时间先后切 train/val/test；窗口在各段内部独立构造；标准化统计量只用训练段。不矛盾：shuffle 打乱的是窗口**样本顺序**（SGD 正常要求），不破坏窗口**内部**的时间结构；禁止的是打乱原始时间点的先后。

**8.** naive 的强弱取决于数据的自相关结构——强周期数据上它看不出周期所以笨，强惯性数据上"复制粘贴"近乎最优。动手前先算 naive，明确要打赢的及格线。
