## 2. 数据集：AG News

### 2.1 是什么

AG News（Zhang et al., 2015）是文本分类的入门级标准基准：新闻标题+摘要，4 分类。

| 属性 | 值 |
|---|---|
| 规模 | 官方 train 120000 条 / test 7600 条（本仓库缓存已是官方全量） |
| 类别 | World / Sports / Business / Sci-Tech，各约 25%（均衡） |
| 输入 | 标题 + 摘要拼成一段文本（几行到几十行词） |
| 本项目默认 | `train_subset: 20000`——2 万条训练足够跑通流程；全量可调 `train_subset: null` |

**下载通道说明**：`data/download.py` 按序尝试 GitHub raw 直连 → gh-proxy 代理 → 内置合成数据兜底。本仓库缓存已是官方全量真实数据，可离线跑全部流程。

## 3. 工程化：与 Fashion-MNIST 项目的三处差异

### 3.1 特征工程从"几乎没有"变成"三步走"

`features.py` 的三个函数就是文本的特征工程，每步都有陷阱：

1. **`simple_tokenize`**（已实现）：小写 + 正则切词。英文按空格/标点切基本够用；
2. **`build_vocab`**：从**训练段**统计词 → id 映射。`[PAD]=0 / [UNK]=1 / [CLS]=2` 占据前三个编号，普通词按词频从高到低排。**词表只能用训练段建**——测试集的词混进词表 = 泄漏（测试里有一条专查这个）；
3. **`encode`**：文本 → 定长 id 序列：句首加 `[CLS]`、超出 `max_len` 截断、不足补 `[PAD]`，同时产出 padding 掩码（True = padding 位置）。

### 3.2 词表是"训练产物"，要随模型保存

图像项目的归一化是无状态的（/255）。文本的词表是**从数据统计出来的有状态产物**——和模块 1 的 StandardScaler 一个性质：训练时统计、预测时复用。所以 train.py 把 `vocab.json` 和 best.pt 一起保存，predict.py 加载同一个词表重新编码。**用错词表的预测不报错，只是悄悄变垃圾**——静默错误的经典形态。

### 3.3 padding mask：注意力不许关注空白

batch 内文本长短不一，全靠 [PAD] 补齐。但 [PAD] 是无意义的占位——`model.forward` 把 padding 掩码传给 `nn.TransformerEncoder` 的 `src_key_padding_mask`，让注意力权重在这些位置恒为 0（前置文档 §4 的掩码机制的调库形态）。`test_padding_mask生效_补pad输出不变` 这条测试专查它：同一句话补不同数量的 PAD，输出必须不变。

## 5. 本项目要做什么（任务清单，数字均为实测）

### 任务 1：Baseline 跑通

实现 features.py + trainer.py 后，默认 config（子集 20000 / max_len 64 / vocab 20000 / d_model 128 / nhead 4 / layers 2 / lr 5e-4 / cosine 调度 / patience 3）直接 `python train.py`。

**实测参考**：词表 20000 词；早停在第 **7** epoch 触发，验证集最优在第 **4** epoch（val_loss=0.4886，val_acc=0.8215）；测试集 **accuracy = 0.8261，macro F1 = 0.8263**（参数量 2,825,476）。差太远先查 §7。

### 任务 2：Trainer 三组件 + 训练曲线

与模块 6 项目同构，唯一区别：`_validate` 除了 loss 还要返回 accuracy（`history["val_acc"]`）。画训练曲线后观察一个有趣现象：**val_loss 第 4 epoch 后就不再下降，val_acc 却还能涨到 0.835**——早停盯 val_loss（交叉熵）而 val_acc 在改善，这是"损失与准确率不同步"的活例子：模型在变 confident 的同时还没变准。

### 任务 3：TF-IDF 正面对比（本项目灵魂）

跑一遍 sklearn 经典管线（TF-IDF 1~2 gram + LogisticRegression，十几行，几秒钟）：

```
TransformerEncoder（本项目）: accuracy = 0.8261
TF-IDF + LogisticRegression : accuracy = 0.8963
```

**经典方法赢了 7 个点**。这不是事故，是本项目的核心收获：

1. **Transformer 的优势在大数据**。AG News 全量 12 万条时 Transformer 能反超；2 万条的小数据上，词表只见过 2 万条文本的词频统计，注意力层学不出足够稳定的词关系。前置文档 §1 讲过"注意力 replacing 循环"，但没讲"注意力需要数据喂"——这次补上；
2. **TF-IDF 是词频统计的直接利用**：新闻分类恰恰是"关键词驱动"的任务（"goals/score"→体育，"stocks/earnings"→商业），词频特征信息密度极高；
3. **什么场景该用什么**：数据少、任务偏关键词 → 经典方法；数据多、任务需要语义理解（指代、否定、长程依赖）→ Transformer。工程上先用便宜的方法建 baseline，再用贵的方法打它。

### 任务 4：混淆矩阵分析

`evaluate.py` 生成混淆矩阵热力图。**实测最大的混淆对：Business → Sci/Tech 282 次、Sci/Tech → Business 195 次**（远超其他类对）。人工看几条被混淆的样本：科技公司的财报新闻、电商平台的算法新闻——两类在词汇层面本来就有大量重叠（company/market/corporate）。**语义可分 ≠ 词面可分**，这正是"上更强的模型（更大规模/预训练）"的动机，也是模块 2 文档 §7"分类评估要找到错误模式"的实战。

### 任务 5：推理演示（实测输出，模型包已保留可直接跑）

```

预测: Sci/Tech（置信度 99.06%）

$ python predict.py --input "Oil prices surge as OPEC agrees to cut output"

$ python predict.py --input "Lakers beat Warriors in overtime thriller"
```

## 6. 特征工程提示

- **分词就是文本的特征工程起点**：本项目手工走的"分词 → 词表 → 编码"三步，正是 transformers 库的 tokenizer 内部做的事（子词 BPE 是它的升级版，解决词表爆炸和未登录词）；
- **可讨论的升级方向（不实现）**：max_len 64 截断会切掉长摘要的尾部（AG News 文本短，影响有限；长文任务要认真定截断策略）；子词分词；预训练词向量初始化 Embedding；
- **终点是预训练**：BERT/GPT 的分类器 = 本项目的结构 + 大规模预训练的权重。本项目手工走完链路的价值，就是让你以后调 transformers 库时知道每个参数底下是什么。

---

## 7. 常见坑（文本特供版）

1. **词表用全量数据建 = 泄漏**：测试集词汇混进词表，评估虚高且毫无察觉（§3.1，测试专查）；
2. **padding 不传 mask**：模型照常关注 [PAD] 位置，短文本的 [CLS] 向量被"空白"污染——不报错，指标静默变差（§3.3 的强测试专查）；
3. **[CLS] 忘了加或取错位置**：句首没加 [CLS]（heads 取到的是一个普通词的输出）或取了别的位置——分类头失去"全文摘要"的语义；
4. **预测时词表/分词与训练不一致**：predict.py 必须用 `features.simple_tokenize` + checkpoint 记录的 vocab.json，自己另写一份分词就是精度静默下降；
5. **末层接 softmax + CrossEntropyLoss**：双重 softmax，训练不报错但 loss 下不去（和模块 4 项目同一个坑，`predict.py` 里只在预测时显式 softmax 一次）；
6. **lr 给太大**：Transformer 对学习率比 MLP 敏感，5e-4 起步，loss 爆炸先降 lr。
