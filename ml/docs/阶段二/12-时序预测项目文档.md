## 2. 数据集：ETTh1

### 2.1 是什么

ETTh1（Electricity Transformer Temperature）是电力变压器的小时级运行数据，时序预测领域公认的基准数据集之一（Zhou et al., 2021）：

| 属性 | 值 |
|---|---|
| 样本数 | 17420 个小时点（2016-07-01 ~ 2018-06-26，约两年） |
| 特征 | 6 路负载（HUFL/HULL/MUFL/MULL/LUFL/LULL）+ **OT**（Oil Temperature，油温） |
| 目标 | `OT`：预测未来 4 个小时点的油温（多变量输入 → 多步输出） |
| 采样 | 1 小时一个点（15 分钟级的是 ETTm1，别搞混） |

七列的含义：HUFL/HULL = 高负载有用/无用（High UseFul/UseLess Load），MUFL/MULL、LUFL/LULL 同理降级。六路负载是"因"，油温是"果"——多变量输入的价值就在于让模型从负载变化里提前读出油温走势。

加载并看一眼（骨架 `data/download.py` 已实现，直接跑）：

```python
from data.download import load_raw_data
import yaml

with open("config.yaml", encoding="utf-8") as f:
    config = yaml.safe_load(f)
df, meta = load_raw_data(config)
print(df.shape)          # (17420, 8)：date + 7 列传感器
print(meta["source"])    # 缓存（来源见首次下载日志）
print(df.describe().round(2))
```

**下载通道说明**：`data/download.py` 按序尝试 GitHub raw 直连 → gh-proxy 代理变体 → 内置合成数据兜底（同构的 7 列合成时序，保证流程永远能跑通）。本仓库的缓存已是**真实 ETTh1**（17420 行，列名与数值范围均已核验），可直接离线跑全部流程。

### 2.2 先做两分钟 EDA

```python
import matplotlib.pyplot as plt

df["OT"].plot(figsize=(12, 3), title="OT 油温（两年）")     # 看到明显的日周期 + 年周期

## 3. 工程化：与 Fashion-MNIST 项目的三处差异

餐厅后厨的岗位划分（模块 1 项目文档 §3）原样搬来，但三个岗位的**工作内容**因时序而变：

### 3.1 划分：按时间切，禁止 shuffle

图像数据集样本互相独立，怎么切都行。时序数据第 t 行和第 t+1 行几乎一样——随机划分等于让模型背邻居，评估数字虚假偏高（前置文档 §6 的实证）。所以 `features.split_by_time` 沿时间轴切 train/val/test（尾部 15%/15%），`val_loader`/`test_loader` 一律 `shuffle=False`。

一个容易迷惑的点：**train_loader 反而要 `shuffle=True`**。因为窗口化之后，每个 (96 历史 → 4 未来) 窗口是独立样本，打乱的是**样本顺序**，不破坏任何窗口内部的时间结构——这与"打乱原始时间点"是两回事。

### 3.2 特征工程：窗口就是特征

时序的"特征工程"核心就一个动作：滑动窗口把 17420 行长序列切成上万个监督学习样本。`make_windows` 的对齐关系是测试逐索引断言的：第 i 个窗口的最后一行是 `series[i+95]`，目标的第一行是 `series[i+96]`——预测绝不偷看窗口内部的信息。**窗口必须在各段内部独立构造**，跨越 train/val 边界的窗口同样是泄漏。

### 3.3 评估：反归一化 + 必须带 naive

模型在标准化空间里训练，报出来的 0.0134 没人看得懂。`evaluate.py` 先用训练段统计量反归一化回"度"，再算 MAE/RMSE；并且永远并排报告 naive baseline（预测 = 窗口最后一个 OT 值，`naive_baseline` 已实现完整）。

模型包（checkpoint）里因此比模块 4 多存了 `scaler`（含训练段均值/方差）、`feature_cols`、`target_col`——predict.py 复现预处理全靠它们。

## 5. 本项目要做什么（任务清单，数字均为实测）

### 任务 1：Baseline 跑通

实现 features.py + trainer.py 后，默认 config（window 96 / horizon 4 / hidden 64 / layers 2 / lr 1e-3 / StepLR(10,0.5) / patience 5）直接 `python train.py`。

**实测参考**：早停在第 **9** epoch 触发，验证集最优在第 **4** epoch（val_loss=0.0134）；测试集（反归一化后）**LSTM MAE = 0.7370，RMSE = 1.0439**。差太远先查 §7。

### 任务 2：Trainer 三组件 + 训练曲线

实现 `fit` / `save_checkpoint` / `check_early_stopping` / `_make_scheduler` 后，用 `history.json` 画出 train/val 双线图（`evaluate.py` 的 `plot_training_curves` 会自动画）。观察点：val loss 的最低点在哪、早停救了你几个 epoch 的无效计算。

### 任务 3：naive baseline 正面对战（本项目灵魂）

`python evaluate.py` 会自动并排对比：

```
测试集（反归一化后，2514 个窗口 × 4 步）:
  LSTM : MAE = 0.7370, RMSE = 1.0439
  naive: MAE = 0.7287, RMSE = 1.0752
  对比: ⚠️ 打不过 naive，模型白干
```

**这是阴性结果，也是本项目最重要的收获**。两个问题必须想明白：

1. **为什么 naive 这么顽固？** OT 强自相关：下 1 小时的油温和当前几乎一样。"明天 = 今天"在短期预测里是极难击败的对手——业界一个真模型如果赢不过 naive，说明它连"惯性"都没学会。
2. **为什么 RMSE 上 LSTM 赢（1.044 < 1.075）、MAE 上却输（0.737 > 0.729）？** RMSE 罚大误差：LSTM 在"油温突变"的样本上比 naive 稳（naive 对突变束手无策，误差巨大），把 RMSE 拉了下来；但大多数平稳样本上 naive 的"复制粘贴"平均精度更高。**一个指标赢、一个指标输**——这正是模块 1 文档 §7 讲过的"指标各有性格"，只是这次亲自撞上了。

结论不是"模型白干"，而是：**平均精度上模型还没赚到超过惯性的钱**。想翻盘？这就是任务 4。

### 任务 4：消融实验（留给你）

我们试过一次盲调（lr 0.005 + patience 12 + epochs 60）：MAE 反而升到 0.7527——**盲目加大训练量不解决结构性问题**。给你几个真正可能改变结构的方向，每个都让测试集 MAE 投票：

- **缩短 horizon 到 1**：naive 在 +1h 处最强，但 LSTM 学"下一小时"也最容易——看看到底谁赢；
- **加大 window_size**（24 → 48 → 96 → 168）：一周的窗口能让模型看到"周周期"；
- **只喂 6 路负载、不喂 OT 历史**：逼模型从"因"推"果"，而不是背惯性；
- **把 naive 当特征**：预测"相对窗口末值的增量"（残差学习），让模型专心学"偏离惯性的部分"——这是业界打 naive 的标准招。

### 任务 5：评估可视化 + 推理演示

1. `evaluate.py` 生成两张图：预测 vs 真实曲线（测试集前 480 点）、训练曲线；
2. `predict.py` 演示（实测输出，模型包已保留可直接跑）：

```

## 6. 特征工程提示

- **窗口本身就是特征工程**：滑窗 + 多变量拼接已经把"时序结构"编码进样本，这是和表格数据最大的不同；
- **时间特征**：把 hour-of-day / day-of-week 编码（sin/cos）拼进特征列，模型更容易抓周期（`df["date"].dt.hour` 起步）；
- **差分**：把 OT 换成 ΔOT（相对上一小时的差）为目标，等于逼模型学"偏离惯性的部分"——和任务 4 的残差学习异曲同工；
- **别贪多**：每加一个特征跑一次实验，测试集 MAE 投票。时序特征工程的调参空间比图像大得多，克制一点。

## 7. 常见坑（时序特供版）

### 7.1 时序泄漏三兄弟（全是静默错误，评估虚高不报错）

1. **随机划分**：`train_test_split(shuffle=True 默认)` 用在时序上 = 模型背邻居（§3.1）；
2. **全量 fit scaler**：均值/方差统计进了未来的分布信息（和模块 1 的 StandardScaler 同一个坑，测试里有一条专查）；
3. **窗口跨段**：train 段末尾 96 行进了某个"训练窗口"，目标却在 val 段——切完段**各段内部独立** `make_windows`。

### 7.2 忘记反归一化就汇报

模型输出在标准化空间，直接汇报 MSE = 0.0134 没有意义。反归一化只针对目标列：`y * scaler.scale_[idx] + scaler.mean_[idx]`——别把 7 列全反了，只有 OT 是目标。

### 7.3 没打 naive 就汇报模型

没有 baseline 的时序报告等于没写。naive 的实现就在 `evaluate.py`（已完整实现），跑一次只要 2 秒。

### 7.4 其他小坑

- **train_loader 的 shuffle=True 是对的**，别看到"时序不能 shuffle"就全部关掉（§3.1 的区分）；
- **单层 LSTM 传 dropout 会报错**：`num_layers=1` 时 dropout 必须为 0（model.py 已处理，`test_单层时dropout不生效` 在守护）；
- **device 不一致**：模型 `.to(cuda)` 后喂 cpu 张量会报 "Expected all tensors to be on the same device"——Trainer 里已统一处理，自己改代码时留意；
- **checkpoint 里没有 scaler**：train.py 会在训练结束后把 scaler 补写进 best.pt——你如果另存了模型却没补，predict.py 会 KeyError。
