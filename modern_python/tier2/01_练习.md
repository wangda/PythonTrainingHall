## 题 1：训练配置模型

从零创建 `exercises/t2_1/train_config.py`：

1. 定义两个模型（嵌套）：
   - `OptimizerConfig`：`name: Literal["adamw", "sgd"]`、`learning_rate: float = Field(gt=0, le=1)`、`weight_decay: float = Field(ge=0, default=0.01)`
   - `TrainingConfig`：`run_name: str`（`min_length=3, max_length=32, pattern=r"^[a-z0-9-]+$"`）、`epochs: int`（`ge=1, le=1000`）、`batch_size: int = Field(ge=1, multiple_of=8)`、`device: Literal["cpu", "cuda", "mps"]`、`optimizer: OptimizerConfig`、`tags: list[str] = Field(default_factory=list)`
   - `model_config`：`extra="forbid"`、`frozen=True`
2. 加一个 `model_validator(mode="after")`：`device == "cuda"` 且 `optimizer.name == "sgd"` 时报错。
3. 底部演示：准备 **5 组非法 JSON 字符串**（缺必填、learning_rate 超界、batch_size 不是 8 的倍数、未知字段、cuda+sgd），逐一 `model_validate_json` 并捕获 `ValidationError`，打印 `e.errors()` 观察 Pydantic 如何定位每个错误。
4. 最后做一次合法 JSON 的 `model_validate_json` → `model_dump_json` → 再 validate 的往返，断言相等。

**验收标准**：`uv run pyright` 零报错；5 组非法数据各自命中**预期的那一个字段**的错误（不是恰好碰巧报错）；往返相等断言通过。

## 题 2：pydantic-settings 替换硬编码配置

起始代码：`exercises/t2_1/hardcoded_config.py`（模块级常量 + 一个假装是训练入口的函数）。

要求：

1. 新建 `exercises/t2_1/train_settings.py`：`TrainSettings(BaseSettings)`，`env_prefix="TRAIN_"`，支持 `.env` 文件；字段类型对应起始代码的常量，`device` 用 `Literal` 收紧。
2. 改写 `hardcoded_config.py`（或新建 `train_entry.py`）：从 `TrainSettings()` 取配置跑"训练循环"（打印每个 epoch 的假 loss 即可）。
3. 写一份 `.env.example`（示例键值，真实 `.env` 不提交——确认根 `.gitignore` 是否已忽略它，没有就在本练习中补上这一条）。
4. 实验并记录：`TRAIN_BATCH_SIZE=abc` 时启动行为是什么？对照原版硬编码，写出"配置错误提前到什么时机暴露"的一句话结论。

**验收标准**：改 `.env` 不改代码即可改变训练参数；非法环境变量在启动瞬间报 `ValidationError`（而不是训练中途炸）。

## 题 3：Pydantic vs dataclass 对比实验

把 T1-1 的 `order_domain.py` 用 Pydantic 重写为 `exercises/t2_1/order_domain_v2.py`（同字段、同方法、`replace` 换成 `model_copy(update=...)`）。

1. 同一批"脏数据"（负价格、零数量、空 sku）分别喂给 dataclass 版和 Pydantic 版，对比行为差异，写进注释。
2. 各实例化 10 万次，用 `time.perf_counter()` 记录耗时差。

**验收标准**：注释里有三条结论——Pydantic 赢在哪、dataclass 赢在哪、你给一个新模块做选择时的判断标准。
