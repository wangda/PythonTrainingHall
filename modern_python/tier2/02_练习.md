## 题 1：match/case 重写表达式求值器

起始代码：`exercises/t2_2/expression_eval.py`——if/elif 链 + 手工下标取值的求值器。

要求（改写为 `exercises/t2_2/expression_eval_match.py`）：

1. 用 `match` 重写，op 分发、参数解构全部走模式匹配，禁止再出现 `expr[1]` 这种裸下标。
2. 新增 `("div", a, b)`：除零在**守卫**里处理（`case ("div", _, b) if b == 0` 抛 `ZeroDivisionError`），而不是事后 if。
3. 新增 `("max", *args)`：用序列解构捕获任意个参数（至少 1 个，少于 1 个走 `case _` 报错）。
4. 对比注释：原版 if/elif 链有哪两个 `match` 直接消灭的问题（提示：漏 else 的默认行为、裸下标的越界风险）。

**验收标准**：`uv run python` 跑通文件底部的断言演示（含 div/max 新用例）；`uv run pyright` 零报错。

## 题 3：Result[T, E] 泛型容器

从零创建 `exercises/t2_2/result.py`，用 **3.12 泛型语法**实现 Rust 风格的 Result：

- `Ok[T]` 和 `Err[E]` 两个类（或一个类两种状态，你选，选型理由写注释）。
- 方法：`unwrap() -> T`（Err 时抛出携带 E 的异常）、`unwrap_or(default: T) -> T`、`map[U](f: Callable[[T], U]) -> Result[U, E]`（Ok 时套用 f，Err 时原样透传）、`is_ok` 属性。
- 类型标注必须让 pyright 能区分：`r: Result[int, str] = Ok(3)` 之后 `r.unwrap()` 推断为 `int`。如果两个类做不到精确区分，试 `type Result[T, E] = Ok[T] | Err[E]`。

**验收标准**：`uv run pyright` 零报错且 `unwrap()` 返回类型被正确推断（把鼠标悬停能看到的推断写在注释里验证）；底部演示 Ok/Err 两条路径。这份 Result 是 T2-4 练习 4 hypothesis 的被测对象，接口别中途改。
