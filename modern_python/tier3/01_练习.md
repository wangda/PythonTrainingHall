## 题 1：白板手写装饰器

起始代码：`exercises/t3_1/flaky_task.py`——两个待装饰的函数（一个慢、一个前两次必失败）。

要求（写在同文件）：

1. **不查资料**手写 `@timer`（打印耗时）和 `@retry(times=3, delay=0.1)`。写完才允许对照文档查漏。
2. 两个函数都装饰，跑通：`flaky_api` 应该在第 3 次尝试成功，`timer` 打印的耗时包含重试等待。
3. 堆叠实验：同时挂 `@timer @retry`，**先在注释里写下预测**（timer 计时含不含重试？），再跑验证。预测错了才是本次练习的收获。
4. 故意去掉 `functools.wraps`，在 REPL 里打印 `flaky_api.__name__` 看后果，把输出记录在注释里。

**验收标准**：重试成功且计时包含等待；有"预测 vs 实测"对照注释；能口头解释两个装饰器的包装顺序。

## 题 2：生成器管线 vs 一次性加载

起始代码：`exercises/t3_1/eager_pipeline.py`——先造 20 万行数据文件，再一次性载入内存做过滤聚合。

要求（改写为 `exercises/t3_1/lazy_pipeline.py`）：

1. 把"读行 → 解析 → 过滤 → 聚合"改写成**生成器管线**：每个阶段一个生成器函数，逐段 `yield`，聚合端才真正消费。全程不出现中间 list。
2. 用 `tracemalloc` 分别测两个版本的内存峰值，数字写进文件顶部注释。
3. 断言两个版本结果完全一致（行数、均值）。
4. 注释回答：如果需求变成"取前 10 个合法值"，你的管线改哪一行就能短路？原版必须改哪里？

**验收标准**：峰值内存对比数据（预期：惰性版低一个数量级以上）；结果一致断言通过；能解释管线每一层的惰性边界在哪。

## 题 3：上下文管理器双实现

从零创建 `exercises/t3_1/ctx_timer.py`：

1. 同一个"计时日志"写两遍：类版（`__enter__`/`__exit__`）+ `@contextmanager` 版，接口一致（`with timer("label") as t: ...`，`t.elapsed` 可读）。
2. 异常路径测试：`with` 块内 `raise ValueError`——两个版本的耗时都**必须**被记录（try/finally 放对位置），异常照常向外抛（`__exit__` 返回 False）。
3. 用 `pytest.raises` 或裸 try/except 验证异常路径，代码即证据。
4. 注释：类版和 `@contextmanager` 版各自的适用场景（提示：需要跨多次进入保持状态时，谁更自然？）。

**验收标准**：正常路径和异常路径计时都正确；异常不被吞；能说出两个版本的选择依据。
