# T3-1 语言底层机制

> 这一梯队不新增"工具"，讲的是 Python 库为什么长成那样。学完能读懂装饰器链、生成器管线和 `with` 背后的机制。

## 1. 装饰器：定义时就生效的函数改写

```python
@timer
def process(data): ...

# 语法糖，完全等价于：
def process(data): ...
process = timer(process)
```

与 Java 注解的本质区别：Java 的 `@Transactional` 只是元数据，要等容器反射扫描才产生行为；Python 装饰器在 **`def` 执行的那一刻**直接改写函数对象，无框架、无容器、无字节码生成。最接近的概念是 Spring AOP——但 Python 把它做成了语言语法。

带参装饰器 = 装饰器工厂（多包一层）：

```python
import functools
import time

def retry(times: int, delay: float = 0.5):
    def decorator(func):
        @functools.wraps(func)          # 保住 __name__/__doc__，不写会丢
        def wrapper(*args, **kwargs):
            for attempt in range(1, times + 1):
                try:
                    return func(*args, **kwargs)
                except Exception:
                    if attempt == times:
                        raise
                    time.sleep(delay)
        return wrapper
    return decorator
```

执行顺序（自检必考）：

```python
@timer
@retry(times=3)
def call(): ...

# 等价：call = timer(retry(times=3)(call))
# 应用自下而上：先被 retry 包装，再被 timer 包装
# 调用时：timer 的前置逻辑 → retry 的循环 → 原函数
```

## 2. 生成器：暂停/恢复的函数

`for` 循环的底层协议：`iter()` 拿迭代器 → 反复 `next()` → `StopIteration` 结束。生成器是实现该协议的最省事方式：

```python
def read_values(path):
    with path.open(encoding="utf-8") as f:
        for line in f:
            try:
                yield float(line.rsplit(",", 1)[1])   # 到 yield 暂停，下次 next 从这继续
            except ValueError:
                continue
```

三个关键性质：

- **惰性**：不 `next` 就一行都不读。100 GB 的文件和 100 行的文件，内存占用一样。
- **单次消费**：迭代一遍就耗尽，再迭代是空——和 Java Stream 一样。
- **可组合成管线**：`sum(v for v in read_values(p) if v > 0)`，每层都是惰性，全程内存恒定。

`send`/`close`：

```python
def accumulator():
    total = 0
    while True:
        x = yield total        # yield 既是出口也是入口
        if x is None:
            break
        total += x

acc = accumulator()
next(acc)          # 启动到第一个 yield（必须先"点火"）
acc.send(10)       # 10 成为 yield 表达式的值 → total=10，返回 10
acc.close()        # 在 yield 处抛 GeneratorExit，协程体收尾
```

ML 关联：PyTorch DataLoader、`langchain` 的流式输出，底层全是这套协议。

## 3. 上下文管理器：with 的机制

```python
class Timer:
    def __enter__(self) -> "Timer":
        self._start = time.perf_counter()
        return self                          # as 后面拿到的就是这个返回值

    def __exit__(self, exc_type, exc, tb) -> bool:
        self.elapsed = time.perf_counter() - self._start
        return False                         # False=异常照常抛出；True=吞掉（慎用）
```

没有 `AutoCloseable` 接口——有这两个方法就行（又是鸭子类型）。对照 Java try-with-resources：资源管理能力相同，但 Python 的 `with` 不限于"关资源"，计时、事务、临时目录、修改后还原（如 `monkeypatch`）都是上下文管理器。

函数式写法（两行前后夹住 yield）：

```python
from contextlib import contextmanager

@contextmanager
def timer(label: str):
    start = time.perf_counter()
    try:
        yield                                # yield 前 = __enter__，后 = __exit__
    finally:
        print(f"{label}: {time.perf_counter() - start:.3f}s")
```

需要动态叠加数量不定的上下文时用 `contextlib.ExitStack`（`with ExitStack() as stack: stack.enter_context(...)`）。

## 4. 描述符：属性访问的钩子

```python
class Positive:
    def __set_name__(self, owner, name):
        self._name = "_" + name
    def __get__(self, obj, objtype=None):
        return getattr(obj, self._name)
    def __set__(self, obj, value):
        if value <= 0:
            raise ValueError(f"{self._name} must be positive")
        setattr(obj, self._name, value)

class Order:
    quantity = Positive()     # 赋值即校验——这就是 pydantic/ORM 字段机制的雏形
```

最重要的洞见——**方法绑定就是描述符**：

```python
a = A()
a.f
# <bound method A.f of ...>
# 等价于 A.__dict__['f'].__get__(a, A)
# self 就是这么来的：函数是描述符，属性访问时自动把实例绑成第一个参数
```

`__getattr__`（只在**找不到**属性时调用）vs `__getattribute__`（每次访问都调用，性能敏感、易递归）。`@property`、`functools.cached_property` 都是这两层机制的现成品，先想它们，真需要再手写描述符。

## 5. import 系统与模块组织

```python
# 包的门面：__init__.py 负责 re-export，调用方不该知道内部文件结构
# modern_python/tier1/exercises/__init__.py 可以是空的；
# 库项目的 __init__.py 惯例：
from .order import Order
from .status import OrderStatus

__all__ = ["Order", "OrderStatus"]     # from x import * 的白名单 + 公共 API 声明
```

规则：

- **没有 private**：`_name` 是"内部使用"的君子协定，`from x import _secret` 技术上可行。
- 循环导入的标准解法：

  ```python
  from typing import TYPE_CHECKING
  if TYPE_CHECKING:
      from .order import Order    # 只给检查器看，运行时不执行——打断环
  ```

- 相对导入（`from .x import y`）只在小范围用；跨层引用一律绝对导入。
- 模块级副作用（顶层执行代码）越少越好——import 一个模块不应产生可见动作。
