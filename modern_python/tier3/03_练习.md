> 前置：读完 `03_项目结构与打包.md`。

> 说明：仓库根部已经是一个可安装项目（`pythontraininghall`），为避免动它，本练习在 `exercises/t3_3/` 下做一个**独立的小包**走完整流程。整目录改造放到你有真实新项目时做，流程完全一致。

## 题 1：从零构建可安装包

在 `exercises/t3_3/` 下创建：

```
t3_3/
└── modern_tools/               # 项目根
    ├── pyproject.toml          # hatchling 后端 + [project.scripts]
    ├── src/
    │   └── modern_tools/
    │       ├── __init__.py     # __version__ + re-export + __all__
    │       ├── core.py         # 统计逻辑：目录下 .py 文件数、总行数、最大文件
    │       └── cli.py          # argparse 入口，main() 薄调度
    └── tests/
        └── test_core.py        # core 的单元测试（用 T2-4 的姿势）
```

1. `core.py` 的 `scan(path: Path) -> ScanResult`：dataclass 结果（文件数、总行数、最大文件名）。参考你 T1-3 题 3 的 pathlib 实现，但**逻辑与打印彻底分离**。
2. `cli.py`：`modern-tools scan <path>` 与 `modern-tools --version`（argparse 足够，想试 Typer 属于加分）。
3. `pyproject.toml`：hatchling 后端、`[project.scripts]` 注册 `modern-tools`。
4. 构建 + 装进干净环境验证：

   ```bash
   cd modern_python/tier3/exercises/t3_3/modern_tools
   uv build
   uv venv /tmp/t3_3_venv
   uv pip install --python /tmp/t3_3_venv/bin/python dist/*.whl
   /tmp/t3_3_venv/bin/modern-tools scan ../../../../tier1/exercises
   ```

5. 反向实验：把 `src/` 改名成 flat 布局重新 build——注释记录装出来的包有什么差异（提示：`site-packages` 里躺了什么）。

**验收标准**：干净 venv 里入口命令真实可用；`uv run pytest`（在包目录里）全绿；注释里有 flat vs src 的实验记录。

## 题 2：把入口钉进测试

1. 给 `cli.main()` 写测试：`capsys` 抓输出断言 `scan` 子命令的打印内容，`monkeypatch` 掉 `sys.argv`。
2. 测试 `--version` 输出与 `__init__.py` 的 `__version__` 一致（防两处手改漂移）。

**验收标准**：CLI 层有测试且不依赖真实文件系统（用 tmp_path 造的目录）；版本号断言生效——手改 `__version__` 而忘记 pyproject 时此测试应当报红（试一下）。
