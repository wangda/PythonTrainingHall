## 题 1：ruff 首检——修一遍你自己的历史代码

1. 安装：`uv add --dev ruff`。
2. 选一个自己的历史模块（如 `ml/` 下任一文件、`numpy_train/simplenet.py`），跑：

   ```bash
   uv run ruff check --select E,F,I,UP,B,SIM numpy_train/simplenet.py
   ```

3. **逐条修复，每修一条先查规则文档**（`uv run ruff rule <编码>`），在提交说明或笔记里记下：规则编码、抓的问题、为什么新写法更好。
4. 禁止 `# noqa` 逃课——每条都要真修或真理解后记录"这条不适合此场景"的理由（用 `# noqa: <编码>` + 行内注释表达，这是唯一合法的逃课方式）。

**验收标准**：目标文件 `ruff check` 清零；有一份规则学习笔记（至少 5 条，写明规则名）。

## 题 2：ruff 配置落地

把 T1-2 文档第 3 节的配置写进根 `pyproject.toml`，然后验证配置生效：

1. 新建 `modern_python/tier1/exercises/t1_2/ruff_bait.py`，内容故意包含至少 4 类问题：

   ```python
   import os
   import sys
   from typing import List, Optional

   def process(items=[]):
       result = []
       if len(items) == 0:
           return result
       if items[0] == None:
           return result
       tmp = items[0]
       unused = "leftover"
       return [str(x) for x in items if x != None]
   ```

2. 跑 `uv run ruff check modern_python/tier1/exercises/t1_2/ruff_bait.py`，记录每条告警的规则编码。
3. 先 `--fix` 自动修，再手动修剩下的；对比哪些被自动修复、哪些必须人判断。
4. `uv run ruff format modern_python/tier1/exercises/t1_2/ruff_bait.py`，看格式化结果。
5. 最后把 `line-length` 临时改成 40，验证有行被新告警，再改回 100。

**验收标准**：最终 `ruff check` + `ruff format --check` 对该文件双清零；笔记里有"自动修 vs 手动修"的清单。

## 题 3：pre-commit 亲眼验红

1. 写 `.pre-commit-config.yaml`（文档第 5 节）并 `pre-commit install`。
2. 故意提交一个含未使用变量的 `.py` 文件，**确认提交被拦下**，保存拦截输出。
3. 修掉问题后重新提交成功。
4. 补做 `pre-commit run --all-files`，如果项目历史文件大面积报错：只修你 `modern_python/` 范围内的，其余文件记录问题清单即可（历史遗留不清理，这是纪律）。

**验收标准**：有"被拦截"和"修复后通过"两份输出记录；历史遗留问题只记录、不擅自清理。
