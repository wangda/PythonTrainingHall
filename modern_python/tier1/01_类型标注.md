# T1-1 类型标注系统

> 前置：Python 3.12 环境。本主题是整个梯队的地基，宁可慢一点，把 Protocol 吃透。

## 1. 与 Java 的根本差异

| 维度 | Java | 现代 Python |
|------|------|-------------|
| 检查时机 | 编译期，类型错误无法运行 | 运行时**不检查**，由 pyright/mypy 静态检查 |
| 强制力 | 语言强制 | 工具链约定（工程上视同强制） |
| 子类型 | 名义子类型：必须 `extends`/`implements` | 类继承是名义的；`Protocol` 引入结构子类型 |
| 泛型运行时 | 类型擦除 | 同样基本不保留，但 dataclass/pydantic 等框架**运行时读取标注** |

两个关键认知：

1. 解释器几乎忽略标注——`def f(x: int) -> str` 传个 list 照样能跑。标注的消费者是**人和静态检查器**。
2. 存在一类"运行时消费标注"的框架：`dataclasses`、`pydantic`、FastAPI。标注在这些场景下是真正的数据（T2-1 展开）。

## 2. 基础语法

```python
# 变量标注（多数时候可以省略，检查器能推断）
count: int = 0

# 函数标注是重点：参数和返回值都写
def format_price(amount: float, currency: str = "CNY") -> str:
    return f"{currency} {amount:.2f}"

# 可能没有返回值
def find_user(uid: int) -> str | None:  # 3.10+ 写法，替代 Optional[str]
    ...
```

## 3. 容器与联合类型（3.9+ / 3.10+ 新写法）

```python
prices: list[float] = [19.9, 42.0]           # 旧写法 List[float] 已过时
stock: dict[str, int] = {"apple": 3}
point: tuple[float, float] = (1.0, 2.0)      # 固定长度、每个位置类型可不同
labels: tuple[str, ...] = ("a", "b")         # 不定长同类型

# 联合类型：3.10+ 用 |，能看懂旧代码即可
def parse(raw: str | bytes) -> int: ...
def fallback(value: int | None = None) -> int: ...
```

Java 对照：`List<String>` → `list[str]`，`Optional<String>` → `str | None`，`Map<String, List<Integer>>` → `dict[str, list[int]]`。

## 4. typing 常用工具

```python
from typing import Any, Callable, Literal, TypedDict

# Any = 放弃检查（尽量不用）；object = "任意对象但只能用对象共有能力"
def debug(value: object) -> None:
    print(repr(value))

# Callable：函数类型，对应 Java 的函数式接口
transformers: list[Callable[[str], int]] = [len, str.count]

# Literal：受限字面量集合，比 String 枚举轻
def set_mode(mode: Literal["read", "write", "append"]) -> None: ...

# TypedDict：给"带固定键的 dict"一个结构（常用于 JSON 边界）
class UserDict(TypedDict):
    name: str
    age: int
```

3.12 新增 `type` 语句，定义类型别名不再需要 `TypeAlias`：

```python
type Vector = list[float]
type Pair[K, V] = tuple[K, V]  # 泛型别名
```

## 5. Protocol（本主题最重要概念）

Java 里你要先声明 `interface Exporter`，实现类必须 `implements Exporter`。Python 的 `Protocol` 反过来：**只要你有这个方法，你就自动满足这个协议**，和继承/声明无关（Go interface 的同款思路）。

```python
from typing import Protocol

class Exporter(Protocol):
    def export(self, title: str, rows: list[tuple[str, int]]) -> str: ...

class PdfExporter:  # 没有继承任何东西
    def export(self, title: str, rows: list[tuple[str, int]]) -> str:
        ...

def render(exporter: Exporter, title: str) -> str:  # 静态检查通过
    return exporter.export(title, [])

# 运行时它本来就是鸭子类型：任何有 export 方法的对象都能传进来
# Protocol 的作用是把"鸭子类型"翻译成静态检查器能理解的语言
```

要点：

- **Protocol 定义在消费方**（调用者），而不是实现方。和 Java 的 interface 放置习惯正好相反——谁用，谁定义自己需要的最小能力面。
- 需要 `isinstance` 检查协议时加 `@runtime_checkable`（只查方法存在，不查签名）。
- 这就是"鸭子类型"的静态化：不问"你是不是 Exporter"，问"你有没有 export"。

## 6. dataclass（对应 Java record）

```python
from dataclasses import dataclass, field, replace

@dataclass(frozen=True, slots=True)
class OrderItem:
    sku: str
    unit_price: float
    quantity: int = 1

@dataclass(slots=True)
class Order:
    items: list[OrderItem] = field(default_factory=list[OrderItem])  # 每实例新建；元素类型显式给出
    status: str = "pending"
```

Java 对照：

| Java record | dataclass |
|-------------|-----------|
| `record Point(int x, int y) {}` | `@dataclass class Point: x: int; y: int`（字段顺序、构造器、`__eq__`、`__repr__` 自动生成） |
| record 不可变 | 默认可变；要不可变加 `frozen=True` |
| `withX(x)` 拷贝方法 | `replace(point, x=10)` |
| 无对应 | `slots=True` 省内存、防误加属性 |

## 6.1 拆解 `field(default_factory=list[OrderItem])`

这行代码同时解决了两个问题：**运行时每个实例拿到独立的列表**，**静态检查器知道列表里装什么**。逐层拆开看。

### 第一层：为什么不能直接写 `items: list[OrderItem] = []`

dataclass 会把这个默认值原样搬进生成的 `__init__` 签名，等价于：

```python
def __init__(self, items: list[OrderItem] = []):   # 这个 [] 在"类定义时"创建一次
    self.items = items
```

所有实例共享**同一个**列表对象：`order_a.items.append(x)` 之后 `order_b.items` 里也会看到 x。这是 Python 的"可变默认参数"陷阱，Java 没有对应问题（Java 的默认值机制不在参数签名里）。

Python 3.11+ 的 dataclass 直接在类定义时拒绝这种写法：

```text
ValueError: mutable default <class 'list'> for field items is not allowed:
use default_factory
```

所以"**可变默认值必须用 `default_factory`**"不是风格建议，是硬性要求。

### 第二层：`field()` 到底是什么

`field()` 不返回默认值，它返回一个 **`Field` 描述对象**（一个 sentinel），上面挂着 `default_factory` 等配置。`@dataclass` 装饰器扫描类的标注，遇到 `Field` 就按"每次实例化时调用一次工厂"来生成 `__init__`：

```python
# @dataclass 生成的东西，手写等价于：
class Order:
    def __init__(self, items: list[OrderItem] | None = None) -> None:
        self.items = [] if items is None else items   # 每次调用都执行 []，天然是新的
```

关键点：**工厂是"每次实例化时调用"，不是"类定义时调用"**——这是它和直接写 `[]` 的本质区别。

`field()` 还能控制别的行为，常用参数：

| 参数 | 作用 |
|------|------|
| `default` | 不可变默认值（与 `default_factory` 二选一） |
| `default_factory` | 零参可调用对象，每次实例化调用一次 |
| `repr` / `compare` | 是否参与 `__repr__` / `__eq__` |
| `init` | 是否出现在 `__init__` 参数里（False 时只能内部赋值） |
| `kw_only` | 只允许关键字传参 |

### 第三层：为什么工厂要写成 `list[OrderItem]`，而不是裸 `list`

先看运行时。`default_factory` 只要求"**零参可调用、返回新对象**"，三种写法都合法：

```python
field(default_factory=list)                    # 裸 list：list() -> []
field(default_factory=lambda: [])              # lambda：-> []
field(default_factory=list[OrderItem])         # 3.9+ 泛型别名：list[OrderItem]() -> []
```

`list[OrderItem]` 在运行时是 `types.GenericAlias` 对象，它**可以被调用**：`list[OrderItem]()` 返回 `[]`。所以它和裸 `list` 在运行时行为完全一样。

差别在静态检查。`field()` 的类型签名大致是：

```python
def field(*, default_factory: Callable[[], _T] | _MISSING_TYPE = ...) -> _T: ...
```

pyright 从工厂的**返回类型**反推 `_T`：

| 工厂写法 | pyright 推出的 `_T` | strict 模式结果 |
|----------|--------------------|-----------------|
| 裸 `list` | `list[Unknown]` | `reportUnknownVariableType` 报错 |
| `lambda: []` | 靠字段标注上下文反推为 `list[OrderItem]` | 通过 |
| `list[OrderItem]` | `list[OrderItem]` | 通过，且**元素类型显式可见** |

所以严格模式的规则是：**`default_factory` 传带元素类型的类型对象**，让"运行时新建"和"静态类型"两个目的同时满足：

```python
items: list[OrderItem] = field(default_factory=list[OrderItem])
mapping: dict[str, int] = field(default_factory=dict[str, int])
tags: set[str] = field(default_factory=set[str])
```

`lambda: []` 也能过 strict，但它把"列表装什么"完全托付给上下文推断——加一个 `cast`、改一次标注就可能失配，显式参数类型更稳。

### 常见坑速查

| 写法 | 运行时 | strict pyright |
|------|--------|----------------|
| `items: list[OrderItem] = []` | 3.11+ 类定义即 `ValueError` | — |
| `field(default_factory=list)` | 正确（每实例新列表） | 报 `list[Unknown]` |
| `field(default_factory=lambda: [])` | 正确 | 通过（依赖上下文推断） |
| `field(default_factory=list[OrderItem])` | 正确 | 通过（推荐） |
| `field(default=[], default_factory=list)` | `TypeError`（二选一） | — |

## 7. Enum

```python
from enum import Enum, StrEnum, auto

class OrderStatus(Enum):
    PENDING = auto()
    PAID = auto()
    CANCELLED = auto()

class LogLevel(StrEnum):        # 3.11+，成员直接当字符串用
    DEBUG = "debug"
    INFO = "info"
```

Java 的 enum 可以带字段和方法，Python 的也可以（成员即实例），但惯用做法是尽量保持简单，需要行为的用 dataclass + 方法。

## 8. pyright strict 工作流

1. VS Code 装 Pylance 扩展，`"python.analysis.typeCheckingMode": "strict"`。
2. CLI 检查：`uv add --dev pyright`，然后 `uv run pyright`。
3. `pyproject.toml` 配置：

```toml
[tool.pyright]
include = ["modern_python/tier1/exercises"]
typeCheckingMode = "strict"
pythonVersion = "3.12"
```

strict 模式的核心规则：所有函数必须有完整标注、不允许隐式 `Any`、`None` 必须显式处理。初见会报很多错——每个报错都在教你一个类型边界。

`# type: ignore` 是逃生舱，只在两种情况用：第三方库缺标注（优先加 `# pyright: ignore[reportMissingTypeStubs]` 这种带错误码的精确忽略）、检查器确实误判。裸的 `# type: ignore` 视为欠债。

### 8.1 报错修复方法论（对号入座）

修复前先建立三个认知：

1. **报错数量 ≠ 问题数量**。`Unknown` 会传染：一个参数没标注，类型就是 Unknown，它的每个属性、每次传递、每个返回值全是 Unknown，于是一行未标注能产生十几个报错。修源头，下游成片消失。
2. **先修签名，再修函数体**。`reportMissingParameterType` / `reportUnknownParameterType` 永远是优先级最高的——它们是其他大部分报错的根。
3. **修一类就重跑一次**（`uvx pyright <目录>` 或编辑器内看），观察剩余错误成片下降，这个过程比一次修完学到更多。

| 错误码 | 典型报错文本 | 在说什么 | 修法 |
|--------|-------------|----------|------|
| `reportMissingParameterType` + `reportUnknownParameterType` | `Type annotation is missing for parameter "rows"` | 参数没标注。**两码总是成对出现**（缺标注 → 推断为 Unknown） | 补标注，一修消两错 |
| `reportUnknownVariableType` / `reportUnknownMemberType` | `Type of "best" is unknown` | 表达式类型推不出来 | **不要在报错行修**。往上找 Unknown 的源头（某个未标注的参数/属性/函数返回），修源头 |
| `reportAttributeAccessIssue` | `Cannot access attribute "items" for class "ShoppingCartItem"` | **很可能是真 bug**：变量实际类型和你以为的不一致。练习里 `cheapest_item` 参数写成 `ShoppingCartItem`，函数体却访问 `ShoppingCart` 才有的 `.items`——这是逻辑错误被静态抓到 | 改函数签名（本例应为 `ShoppingCart`），不是加 ignore |
| `reportArgumentType` | `Argument of type "ShoppingCart" cannot be assigned to parameter of type "ShoppingCartItem"` | 上一条同一 bug 在调用点的视角（两个报错互为印证） | 顺着报错读两侧类型，判断该改签名还是改调用 |
| `reportOptionalMemberAccess` | `"x" is not a known attribute of "None"` | 函数声明返回 `X \| None`，你没处理 None 就直接 `.field` | 三选一：`if x is None: ...` 分支处理 / `assert x is not None` / 提前 return。这是 strict 最常教育你的"空值边界" |
| `reportReturnType` | `Returned type "X \| None" is not assignable to declared return type "X"` | 有分支漏 return，或某分支返回 None | 补分支；确实可能无返回值就把声明改成 `X \| None` |
| `reportMissingTypeStubs` | `Stub file not found for "xxx"` | 第三方库没带类型标注，不是你的错 | 首选装官方 stubs（`xxx-stubs`）；没有就精确忽略 `# pyright: ignore[reportMissingTypeStubs]` |
| 其他 strict 特有高压线 | `reportImplicitStringConcatenation` 等 | strict 默认全开的部分规则对练习代码过严 | 查明规则语义后，在 `[tool.pyright]` 里对该规则显式降级（`"none"` / `"warning"`），**降级要留注释说明理由** |

修不动的判断顺序：先怀疑自己写错了（`reportAttributeAccessIssue` / `reportArgumentType` 出现时尤其如此）→ 再查是不是类型该改（标注太窄）→ 最后才考虑 ignore / 降级。顺序反了就是用逃生舱掩盖 bug。
